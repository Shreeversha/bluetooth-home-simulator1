Bluetooth-controlled home automation

Arduino UNO + HC-05 + three LEDs on a breadboard. No relays, no mains. Virtual Bluetooth link: the radio and phone are simulated; command parsing and LED control follow the real sketch.

    LED current is about (5 V − 2 V) / 220 Ω ≈ 14 mA, inside the UNO's 20 mA per-pin comfort range. The divider gives 5 V × 2k / (1k + 2k) ≈ 3.3 V at HC-05 RXD.

    Arduino sketch
    /*
  Bluetooth-Controlled Home Automation (LED demo)
  Board : Arduino UNO
  Module: HC-05 in data mode, 9600 baud
  Wiring: HC-05 TXD -> D2, HC-05 RXD <- D3 (via 1k/2k divider)
          Red LED D7, Yellow LED D8, Green LED D9 (220 ohm each)
  Commands: R1/R0, Y1/Y0, G1/G0 (anything else is ignored)
*/
#include <SoftwareSerial.h>

SoftwareSerial BT(2, 3);          // RX = D2, TX = D3

const byte RED_PIN    = 7;
const byte YELLOW_PIN = 8;
const byte GREEN_PIN  = 9;

char buf[2];                      // one 2-character command
byte count = 0;

void setup() {
  pinMode(RED_PIN, OUTPUT);
  pinMode(YELLOW_PIN, OUTPUT);
  pinMode(GREEN_PIN, OUTPUT);
  digitalWrite(RED_PIN, LOW);     // all LEDs start OFF
  digitalWrite(YELLOW_PIN, LOW);
  digitalWrite(GREEN_PIN, LOW);

  BT.begin(9600);
  Serial.begin(9600);             // optional: debug on Serial Monitor
  Serial.println(F("Ready"));
}

void loop() {
  while (BT.available()) {
    char c = BT.read();
    if (c == '\n' || c == '\r') { // end of line: start a fresh command
      count = 0;
      continue;
    }
    buf[count++] = c;
    if (count == 2) {             // full command received
      handleCommand(buf[0], buf[1]);
      count = 0;
    }
  }
}

void handleCommand(char device, char action) {
  int pin = -1;
  if      (device == 'R') pin = RED_PIN;
  else if (device == 'Y') pin = YELLOW_PIN;
  else if (device == 'G') pin = GREEN_PIN;

  if (pin == -1 || (action != '0' && action != '1')) {
    Serial.print(F("Ignored: "));
    Serial.print(device);
    Serial.println(action);
    return;                       // invalid command: do nothing
  }
  digitalWrite(pin, action == '1' ? HIGH : LOW);
  Serial.print(device);
  Serial.println(action == '1' ? F(" ON") : F(" OFF"));
}
    Test procedure
    1. Tap Connect: status turns green and the HC-05 LED changes from fast to slow blink.
    2. Tap Red ON: log shows R1, the red LED glows, D7 reads 5 V.
    3. Tap Yellow ON, then Green ON: all three light, each independently.
    4. Tap Red OFF: only red turns off (R0); yellow and green stay on.
    5. Tap Send invalid command: the Arduino logs it as ignored and nothing changes.
    6. Tap Reset: all LEDs go OFF.
    What is simulated and what is virtual

    Modeled: the wiring and pin labels, HIGH/LOW pin states, LED on/off behavior, and the byte-by-byte command parser, which is a JavaScript port of the sketch above (same 2-character buffer, newline handling and invalid-command rule).

    Virtual: the Android phone, the Bluetooth radio and pairing, and timing. The page does not run the compiled .ino or a real electrical simulation.

    Limitations: this was not verified in Wokwi or Cirkit Designer, so it is a standalone browser simulation. On real hardware the HC-05 must be paired with the phone and be in data mode at 9600 baud (AT mode defaults differ), and a serial Bluetooth terminal app can send the same commands.
